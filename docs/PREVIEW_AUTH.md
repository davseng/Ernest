# Preview sign-in cookie isolation

The owner reported that a new email link returned to the email-entry form on the fixed preview domain. Code inspection found that Preview and Production both used `__Secure-authjs.session-token`. A browser can send a stale parent-domain cookie and a newer exact-host cookie with that same name. A real Auth.js regression test reproduces a null session when the stale cookie appears first, even though the newer session is valid. This demonstrates a matching failure path, not yet a diagnosis from live browser logs.

Vercel Preview now uses distinct `__Host-ernest-preview.*` session, callback and CSRF cookies. They are Secure, HttpOnly, SameSite=Lax, Path=/, with no Domain attribute. Preview ignores AUTH_COOKIE_DOMAIN for those cookies. Existing production cookies are neither removed nor read as preview sessions. Production and local cookie configuration retain their prior behavior. No database schema change, authentication bypass or SMTP/provider change is involved.

The integration test executes the real Auth.js callback and session handlers with the actual PostgreSQL adapter and synthetic auth tables under PGlite. It verifies a valid single-use email token creates a persisted session, session lookup succeeds despite stale legacy cookies, legacy cookies alone do not authenticate Preview, replay fails, and Production cookie options are unchanged. No real recipient, token, database credential or session is used.

After the Preview deployment is Ready, open the fixed preview domain, request a fresh link and open the newest email once in the same browser. One new Preview login is expected because the cookie name changed. Do not change Production settings or clear parent-domain cookies as a workaround. If the loop remains, inspect redacted Vercel authentication logs and effective callback host/database configuration; click tracking, token consumption, database adapter errors and other callback failures remain possible. Never share full email callback URLs, cookies or SMTP/database credentials. Live success requires the owner's browser confirmation.

# Ernest v0.12: owner-reviewed knowledge

## Implementation and release status

Implemented on `feature/v0.12-simplified-review`, based on production commit
`bc23d16f1971e79e2da1447bb880b0207ef66200`. Existing Neon storage, private R2
documents, authentication and records are retained. No production changes,
live migration, Preview deployment or merge were performed for this release.

The chat now investigates with one planner and prepares an editable review.
Only the owner's Save action writes definitive records. Maintenance, spare
consumption, inventory, knowledge and survey updates can be reviewed together
and saved atomically. Missing dates, engine hours and quantities remain unknown.
Manual blank forms also work without the model. Saved reviews have persistent
receipts and before/after history; retries return the original receipt.

Manage links to Boat Knowledge, History, Survey and Reviews. Boat Knowledge is
a readable view generated from existing records, not another editable store.
Older maintenance logs remain visible without being silently converted.
Document extraction no longer automatically resolves findings.

Survey records preserve identifiers, wording, pages and sources. Documented
repair, partial repair and owner-confirmed resolution are distinct. The owner
must explicitly confirm that an A/B list is complete; selected source pages
do not establish completeness by themselves.

2. Run the complete contents of
   `scripts/v012/sql-editor/01-preflight.sql`. Existing prerequisite tables must

3. Run the complete contents of
   `scripts/v012/sql-editor/02-apply-026.sql` once, as one transaction. This

   different database name. It cannot detect which Neon branch the SQL Editor
   selected. On any error, run `ROLLBACK;` and report the error; do not improvise.

## Production gate and deferred work

Production rollout requires the owner's explicit approval, a separate production

deployment. Never copy the staging connection or credentials into production.

scheduling, bulk inventory import and offline expansion are deferred. Existing
historical helpers remain for compatibility; new chat writes use the review path.

## Preview form-loading correction

The first live form-opening test failed. Review JSON writes now use explicit
`sql.json`/`tx.json` parameters rather than pre-stringified values with an inferred
jsonb type. Reads and approval also decode already-created string-form drafts,
so existing pending review links remain usable without another migration. The
regression harness now exercises inferred-jsonb string encoding as well as typed
JSON, legacy draft reopening, save receipts and exactly-once replay. Live form
acceptance must be repeated after the correction deployment.

## Remaining-stock and form simplification follow-up

Owner acceptance confirmed that the review link, editing, saving and maintenance
history work. Unknown inventory balance remained unknown, but the form lacked
an input for the owner's verified remaining count. Maintenance forms now offer
“Remaining quantity after this work”. This is an absolute post-work count,
including zero; it is never combined with another deduction. It uses the same
stock snapshot, audit, ownership and transaction checks. No migration is needed.
The form starts with editable fields; optional guidance, missing-information
notes and interpretation reasons are collapsed at the bottom.

Validation: full 122-test suite passed before adding the new regression; all 15
review-workflow tests then passed including unknown stock to verified four,
exactly-once retry and rejection of a simultaneous deduction. Browser checks
passed including the new remaining-count input and collapsed guidance. Lint,
typecheck and production build passed. Live acceptance of this follow-up remains.

Remaining release gates: owner checks the count/editing flow, survey A/B review
against originals and work orders, and document/diagram access. Then prepare a
draft PR and a separate explicitly approved production rollout. No new feature

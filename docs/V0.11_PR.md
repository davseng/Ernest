# Ernest v0.11: improve retrieval, durable knowledge and confirmed actions

Ernest could miss documents named in a question, discard short identifiers such as D8, bury owner corrections in recent logs, and overwrite a procedure from a stale proposal. The active answer path also bypassed the established constitution. This branch brings chat and search onto one retrieval pipeline and adds durable, owner-confirmed knowledge and revision-protected procedure execution.

- Retrieve titles, filenames, short identifiers, native text and visual relationships with bounded context; optionally combine provider embeddings. Preserve follow-up subjects and source links.
- Store current facts, observations, operational status, effective dates, provenance and supersession without deleting history. Display confirmation cards and saved history under Knowledge.
- Preserve managed-procedure revisions, reject stale updates and report the actual steps changed. Original PDFs remain immutable.
- Reuse the full answer constitution, inspect relevant original PDFs and supported equipment photos, and distinguish unverified visual interpretation from current confirmed facts.
- Normalize document dates and expose text, visual, semantic and understanding status. Allow later visual page windows without losing earlier interpretations.

Typecheck and production build pass. Lint passes with two existing warnings. `git diff --check` passes. Anonymous production-server smoke checks verify the sign-in page, auth provider endpoint, protected-page redirects, unauthorized inbox rejection and private-original redirect.

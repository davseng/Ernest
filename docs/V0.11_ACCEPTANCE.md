## Storage and execution boundaries

Migration `025_competence_memory_action.sql` is additive. `owner_knowledge` keeps owner-confirmed facts and supersession links; historical document findings remain independent evidence. Current facts with the same normalized subject/predicate require explicit replacement. The owner/asset row lock serializes confirmation; the old record remains queryable. Current facts outrank older evidence in model context. Conflicting unrelated records are disclosed rather than automatically deleted or merged. Confidence `1` means explicit owner confirmation, not an objective guarantee of correctness; approximate statements retain their wording.

`knowledge_fact` is a confirmation-card proposal, never an automatic write. Session identity selects the owner on every execution. A missing, stale, unauthorized or failed write cannot return a successful confirmation. Procedure changes have the same boundary, plus optimistic revision checks. Existing imported PDFs are immutable. Existing source-linked managed procedures can be edited; a PDF alone is not an editable managed procedure. Use the existing procedure extraction/review workflow to create an approved managed copy first.

Equipment photographs are retrieved by title, notes, filename and linked component name. Up to two JPEG/PNG/WebP originals (8 MiB each) can be inspected on demand; HEIC/HEIF need a supported conversion and produce an explicit warning. Photo interpretations do not become verified equipment facts. Photo-content semantic indexing is deferred.

Visual interpretations are always unverified evidence. Original PDFs remain in private storage; page numbers refer to the original PDF. The model can inspect up to two originals, each at most 12 MiB, during relevant questions. Visual extraction processes at most 12 pages per request and reports larger documents as partial. Use the visual start-page control to process later page windows; prior interpretations are retained. Separate raster-page storage and background processing queues are deferred; the original PDF retains all page images.

Optional semantic indexing uses provider embeddings stored as JSON vectors, avoiding a mandatory pgvector extension. Set `ERNEST_SEMANTIC_RETRIEVAL_ENABLED=true` and optionally `OPENAI_EMBEDDING_MODEL` (default `text-embedding-3-small`), then reprocess documents. It indexes up to 6,000 characters per page in batches of 64. Retrieval examines at most 2,000 owner-scoped page vectors. Lexical search remains available when embeddings are disabled or unavailable. Larger libraries need vector-index infrastructure and measured recall evaluation.

Answer generation respects `OPENAI_THINK_MODEL`, then `OPENAI_MODEL`, then the repository's established reasoning-family fallback `gpt-5.6-sol`. Normal answers use medium reasoning; Think harder uses high. This favors competence at extra latency/cost. Classification uses `OPENAI_MODEL` when configured. OCR respects `OPENAI_OCR_MODEL`. Model availability, PDF support, latency, token consumption, and costs require measurement with the actual provider account; no live model comparison was possible here. Do not infer a quality improvement solely from the default model change.

The domain retrieval, knowledge, vector and visual-validation primitives do not depend on a cloud database. Full offline export/import of the new tables is deferred; existing offline behavior is preserved. No Ernest 2.0 website-consolidation work is included.
